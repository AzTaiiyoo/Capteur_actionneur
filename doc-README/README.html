1. Introduction

1.1 Objectif du projet

Ce projet vise à développer un système embarqué sur microcontrôleur STM32F407 VGT permettant d'interfacer un capteur de distance à ultrasons (HC-SR04) avec un servo-moteur. L'objectif principal est de créer un système capable de réagir à l'environnement (mesure de distance) ou à des commandes utilisateur (via liaison série) pour positionner précisément un servo-moteur.

Points clés du projet :
  • Système distribué entre STM32F4 et Raspberry Pi, communiquant via UART
  • Un servo-moteur connecté à chaque plateforme (STM32F4 et Raspberry Pi)
  • Capteur ultrason HC-SR04 connecté à la STM32F4
  • Interface utilisateur via console sur la Raspberry Pi
  • Plusieurs modes de fonctionnement configurables

Le système met en œuvre différentes technologies et compétences en développement embarqué :

  • Mesure de distance par ultrasons
  • Génération de signaux PWM pour contrôler des servo-moteurs
  • Communication série formatée entre microcontrôleur et ordinateur
  • Programmation multi-thread sur Raspberry Pi
  • Gestion d'une machine à états
  • Développement modulaire avec séparation des responsabilités
  • Communication entre STM32 et Raspberry Pi
  • Interface utilisateur en mode console

1.2 Modes de fonctionnement

Le système propose trois modes de fonctionnement distincts :

  1. Mode IDLE (repos) :
    • Les LEDs sont éteintes sur la STM32
    • Les deux servo-moteurs (STM32 et Raspberry Pi) sont positionnés au centre (position neutre)
    • Le système attend une commande utilisateur
  2. Mode 1 (asservissement par capteur) :
    • La LED bleue est allumée sur la STM32 pour indiquer ce mode
    • Les deux servo-moteurs (STM32 et Raspberry Pi) se positionnent proportionnellement à la distance mesurée par le capteur HC-SR04
    • Plage de mesure valide : 5 à 25 cm
    • Si la distance est hors de cette plage, les servo-moteurs reviennent en position centrale
    • La STM32 envoie régulièrement les mesures de distance à la Raspberry Pi
  3. Mode 2 (contrôle par commande série) :
    • La LED verte est allumée sur la STM32 pour indiquer ce mode
    • Le servo-moteur de la STM32 se positionne selon une valeur envoyée par l'utilisateur via la console de la Raspberry Pi
    • Le servo-moteur de la Raspberry Pi continue de suivre la distance mesurée par le capteur
    • Plage de valeurs acceptées pour le servo STM32 : 1 à 12 (correspondant à différentes positions angulaires)

En plus des modes de fonctionnement principaux, le système offre les caractéristiques suivantes :

  • Protocole de communication série structuré :

3. Modules développés

3.1. Module HC-SR04

Le module HC-SR04 gère l'interfaçage avec le capteur ultrasonique pour mesurer la distance.

Fonctionnalités principales

  • Initialisation des broches GPIO et du timer
  • Génération d'impulsions précises de 10µs pour le trigger
  • Mesure du temps d'écho avec une résolution microseconde
  • Conversion du temps d'écho en distance (cm)
  • Filtrage des mesures hors plage (5-25 cm)
  • Mise à jour périodique des mesures en Mode 1

3.2. Module Servo-moteur

Le module servo-moteur permet de contrôler la position angulaire d'un servo standard via un signal PWM.

Fonctionnalités principales

  • Initialisation du timer PWM (TIM3)
  • Positionnement précis du servo à une valeur spécifiée
  • Conversion de distances (5-25 cm) en positions servo (1000-2000 µs)
  • Conversion de valeurs utilisateur (1-12) en positions servo
  • Position centrale par défaut (1500 µs, 90°)

Détails techniques

  • Signal PWM généré à 50Hz (période de 20ms)
  • Largeur d'impulsion variable entre 1ms (0°) et 2ms (180°)
  • Position centrale à 1.5ms (90°)
  • Résolution temporelle de 1µs

3.3. Module UART

Le module UART gère la communication série avec l'utilisateur, offrant une interface formatée pour les commandes et les messages d'état.

Fonctionnalités principales

  • Envoi de messages formatés avec délimiteurs
  • Réception non-bloquante de commandes
  • Écho des caractères reçus
  • Gestion des dépassements de buffer
  • Support pour les commandes textuelles et numériques

Protocole de communication

Type de message Format Exemple Description
Commande mode <commande> <mode1> Change le mode de fonctionnement
Valeur servo <valeur> <8> Positionne le servo en Mode 2
Information <message> <Distance: 15.32 cm> Retour d'information
Erreur <message d'erreur> <Error: Message too long> Indication d'une erreur

Commandes reconnues :

  • mode1 : Active le Mode 1 (suivi par capteur)
  • mode2 : Active le Mode 2 (commande manuelle)
  • quit : Retourne au mode IDLE
  • 1 à 12 : Valeurs pour positionner le servo en Mode 2
  • getdistance : Demande la dernière distance mesurée
  • demo : Lance une séquence de démonstration

3.6. Modules Raspberry Pi

La Raspberry Pi est organisée en plusieurs modules qui travaillent ensemble pour offrir les fonctionnalités requises. Chaque module gère un aspect spécifique du système.

3.6.1. Module GPIO

Ce module (fichiers gpio.c et gpio.h) gère l'accès aux broches GPIO de la Raspberry Pi en utilisant l'interface sysfs.

Fonctionnalités principales :
  • Initialisation des broches GPIO et définition de leur direction (entrée/sortie)
  • Contrôle de l'état des broches (écriture de valeurs 0 ou 1)
  • Gestion du servo-moteur connecté au GPIO 18
  • Interface par fichiers système pour un contrôle précis des broches

Fonctions importantes :

  • setupGPIO() : Configure la broche du servo-moteur en sortie
  • exportGPIO() : Rend la broche accessible via l'interface sysfs
  • setGPIODirection() : Définit si la broche est une entrée ou une sortie
  • writeGPIO() : Écrit une valeur sur la broche (0 ou 1)

3.6.2. Module Serial

Ce module (fichiers serial.c et serial.h) gère la communication UART entre la Raspberry Pi et la STM32F4.

Fonctionnalités principales :
  • Établissement de la connexion série à 115200 bauds, 8N1
  • Envoi de commandes formatées à la STM32 avec les délimiteurs < et >
  • Réception et interprétation des données de distance
  • Analyse des messages reçus pour extraire les informations pertinentes

Fonctions importantes :

  • openSerialConnection() : Ouvre et configure le port série
  • sendCommand() : Envoie une commande formatée à la STM32
  • receiveDataThread() : Thread dédié à la réception des données

Le module serial inclut un thread dédié qui s'exécute en arrière-plan et analyse en continu les données reçues de la STM32. Il extrait notamment les informations de distance mesurées par le capteur à ultrasons et les met à disposition des autres modules via des variables partagées protégées par mutex.

3.6.3. Module Servo

Ce module (fichiers servo.c et servo.h) gère le contrôle du servo-moteur connecté à la Raspberry Pi.

Fonctionnalités principales :
  • Génération de signaux PWM précis via GPIO logiciel
  • Conversion de distances mesurées en positions servo
  • Conversion de valeurs utilisateur en positions servo
  • Thread dédié à la génération du signal PWM

Fonctions importantes :

  • distanceToPosition() : Convertit une distance mesurée en position du servo
  • valueToPosition() : Convertit une valeur utilisateur en position du servo
  • pwmThread() : Thread qui génère le signal PWM
  • servoControlThread() : Thread qui contrôle le servo selon le mode actuel

Le module servo utilise deux threads distincts :

  • Un thread PWM qui génère précisément les impulsions pour le servo-moteur
  • Un thread de contrôle qui détermine la position du servo selon le mode et les données disponibles

3.6.4. Module Main

Ce module (fichiers main.c et common.h) orchestre l'ensemble du système sur la Raspberry Pi.

Fonctionnalités principales :
  • Initialisation de tous les modules
  • Création et gestion des threads
  • Interface utilisateur en ligne de commande
  • Traitement des commandes utilisateur
  • Gestion des modes de fonctionnement
  • Nettoyage des ressources à la fermeture

Fonctions importantes :

  • main() : Point d'entrée du programme
  • handleUserInput() : Gère l'interface utilisateur
  • printHelp() : Affiche l'aide sur les commandes disponibles
  • cleanup() : Libère les ressources et arrête proprement le système

Le fichier common.h définit les constantes partagées et les variables globales utilisées par tous les modules, notamment :

  • Numéros de broches GPIO
  • Limites de positions pour le servo-moteur
  • Limites de distances pour le capteur
  • Variables partagées comme le mode actuel, la distance mesurée, etc.

5. Interaction Raspberry Pi - STM32

L'interaction entre la Raspberry Pi et le STM32 constitue un aspect essentiel de ce projet, permettant de créer un système distribué où chaque plateforme joue un rôle complémentaire.

5.1 Architecture du système global

Le système global suit une architecture maître-esclave où la Raspberry Pi agit comme maître et le STM32 comme esclave :

Composants principaux :
  • STM32F4 : Gère le capteur HC-SR04 et son propre servo-moteur
  • Raspberry Pi : Contrôle un second servo-moteur et sert d'interface utilisateur
  • Communication UART : Lien bidirectionnel entre les deux plateformes
  • Interface utilisateur : Console en mode texte sur la Raspberry Pi

Cette architecture présente plusieurs avantages :

  • Répartition des tâches : Le STM32 s'occupe de l'interfaçage avec le capteur à ultrasons, tandis que la Raspberry Pi gère l'interface utilisateur et le traitement de plus haut niveau
  • Redondance : Si l'une des plateformes rencontre un problème, l'autre peut continuer à fonctionner partiellement
  • Flexibilité : L'architecture permet d'ajouter facilement de nouvelles fonctionnalités sur l'une ou l'autre plateforme
  • Apprentissage : Cette configuration permet d'explorer les contraintes et avantages des deux types de systèmes
  • STM32F407 VGT avec capteur HC-SR04 et servo-moteur
  • Raspberry Pi avec son propre servo-moteur
  • Communication UART entre les deux systèmes
  • Interface utilisateur sur la Raspberry Pi

5.2 Fonctionnalités de la Raspberry Pi

Dans ce système distribué, la Raspberry Pi remplit plusieurs rôles :

  1. Interface utilisateur : La Raspberry Pi fournit une interface en ligne de commande permettant à l'utilisateur de contrôler l'ensemble du système. Cette interface propose des commandes intuitives pour changer de mode, définir des positions ou récupérer des informations.
  2. Point de contrôle central : La Raspberry Pi sert de coordinateur pour l'ensemble du système, transmettant les commandes au STM32 et gérant les états globaux du système.
  3. Contrôle du servo-moteur : La Raspberry Pi contrôle son propre servo-moteur qui réagit soit aux distances mesurées par le capteur (transmises par le STM32), soit aux commandes utilisateur selon le mode actif.
  4. Traitement des données : La Raspberry Pi récupère les données de distance depuis le STM32, les traite et les affiche dans un format compréhensible pour l'utilisateur.
  5. Diagnostic et débogage : La Raspberry Pi fournit des outils pour diagnostiquer le fonctionnement du système, comme la commande getdistance pour vérifier la dernière mesure ou le programme minicom.c pour tester la communication série.

La communication entre la Raspberry Pi et le STM32 utilise un protocole série simple mais robuste :

Caractéristiques du protocole :
  • Messages encapsulés entre délimiteurs < et >
  • Format texte pour faciliter le débogage
  • Commandes courtes et explicites
  • Confirmations systématiques des commandes
  • Transmission régulière des mesures de distance

Types de messages échangés :

Direction Type de message Exemple Description
Raspberry Pi → STM32 Commande de mode <mode1> Change le mode de fonctionnement
Raspberry Pi → STM32 Position servo <8> Définit la position du servo STM32 (1-12)
Raspberry Pi → STM32 Demande de distance <getdistance> Demande la dernière mesure de distance
STM32 → Raspberry Pi Mesure de distance <Distance: 15.32 cm> Transmet une mesure de distance
STM32 → Raspberry Pi Confirmation <Mode 1 activated> Confirme une commande reçue
STM32 → Raspberry Pi Erreur <Error: Invalid command> Signale une erreur dans une commande

Pour assurer une communication fiable, la fonction sendCommand() a été implémentée avec un mécanisme spécial : elle envoie chaque caractère individuellement avec un petit délai entre chaque envoi. Cette approche, bien que plus lente, évite les pertes de données qui peuvent survenir lorsque le buffer du récepteur est saturé. 

void sendCommand(int fd, const char* command) {
    if (fd < 0) return;
    
    // Formater la commande
    char formattedCommand[64];
    snprintf(formattedCommand, sizeof(formattedCommand), "<%s>", command);
    
    // Assurez-vous que chaque caractère est envoyé correctement
    for (int i = 0; i < strlen(formattedCommand); i++) {
        write(fd, &formattedCommand[i], 1);
        // Petit délai entre chaque caractère
        usleep(1000); // 1ms
    }
    
    printf("Commande envoyée: %s\n", command);
}

5.6 Implémentation multi-thread

Une des particularités de l'implémentation sur Raspberry Pi est l'utilisation de plusieurs threads pour gérer différentes tâches en parallèle :

  1. Thread PWM : Ce thread génère le signal PWM pour contrôler le servo-moteur. Il calcule précisément les timings nécessaires pour produire une impulsion de la durée adéquate toutes les 20ms (50Hz).
  2. Thread de réception série : Ce thread surveille en permanence le port série pour recevoir et traiter les messages provenant du STM32, notamment les mesures de distance.
  3. Thread de contrôle servo : Ce thread calcule la position que doit prendre le servo en fonction du mode actif et des données disponibles (distance mesurée ou commande utilisateur).
  4. Thread principal : Ce thread gère l'interface utilisateur, traite les commandes et les transmet au STM32.

Pour coordonner ces threads et éviter les problèmes d'accès concurrent, le programme utilise des mutex qui protègent les variables partagées comme le mode actuel, la distance mesurée ou la position du servo. 

// Exemple d'utilisation de mutex pour protéger l'accès aux variables partagées
pthread_mutex_lock(&mutex);
int mode = currentMode;
float distance = currentDistance;
pthread_mutex_unlock(&mutex);

// Traitement avec les valeurs récupérées
if (mode == 1) {
    // Utilisation des données en mode 1
} else if (mode == 2) {
    // Utilisation des données en mode 2
}

Cette architecture multi-thread permet au système de gérer plusieurs tâches simultanément, comme la génération précise du signal PWM pendant que les données série sont reçues et que l'utilisateur entre des commandes.

            printf("\nMessage complet: %s\n", buffer);
            inMessage = 0;

            buffer[bufferIndex] = c;
            bufferIndex++;
        }

    }

}

6. Conclusion et perspectives

Ce projet a permis de développer un système complet intégrant :

  1. Architecture multi-systèmes : Collaboration entre un microcontrôleur STM32 et une Raspberry Pi pour créer un système distribué de contrôle.
  2. Communication inter-système : Utilisation de l'UART pour permettre l'échange d'informations entre les deux plateformes.
  3. Interface capteur-actionneur : Traitement des données du capteur ultrason pour contrôler les servo-moteurs en temps réel.
  4. Machine à états robuste : Gestion explicite des différents modes de fonctionnement avec transitions sécurisées.
  5. Interface utilisateur bi-plateforme : Interaction possible via l'interface série du STM32 ou via l'application console de la Raspberry Pi.
  6. Programmation multi-thread : Utilisation de plusieurs threads sur Raspberry Pi pour gérer différentes tâches en parallèle.
  7. Développement modulaire : Architecture logicielle organisée en modules réutilisables et bien séparés.

Améliorations futures

Plusieurs pistes d'amélioration pourraient être explorées :

  • Interface graphique : Développement d'une interface graphique sur la Raspberry Pi pour visualiser les mesures de distance et contrôler les actionneurs de manière plus intuitive.

  • Extension des capteurs : Ajout de capteurs supplémentaires (température, humidité) pour enrichir les fonctionnalités et créer un système plus complet.
  • Communication sans fil : Remplacement de la liaison UART par une communication Bluetooth ou WiFi pour plus de flexibilité dans le placement des composants.
  • Enregistrement de données : Implémentation d'un système de logging et d'analyse des données sur la Raspberry Pi pour suivre l'évolution des mesures dans le temps.
  • Serveur/client : Développement de l'application sous forme d'un serveur/client pour permettre un contrôle à distance via un navigateur web ou une application mobile.
  • Historisation des mesures : Enregistrement des 200 dernières valeurs de distance et génération de fichiers pour analyse statistique ou visualisation graphique.
  • Amélioration du PWM sur Raspberry Pi : Utilisation d'une bibliothèque dédiée
